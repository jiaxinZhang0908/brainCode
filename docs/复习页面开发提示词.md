## 提示词

### 背景

本项目是一个本地优先的个人知识与复习工作台（Vite + React 19 前端，Spring Boot 3.5 + SQLite 后端）。复习排期已接入 FSRS（`io.github.open-spaced-repetition:fsrs:1.0.0`），后端适配层在 `backend/src/main/java/local/braincode/review/FsrsReviewScheduler.java`，接口层在 `ReviewController.java`，前端页面在 `frontend/src/pages/review/ReviewPage.jsx` 和 `api/reviewApi.js`。

现有能力：创建复习卡片（关联已有/新建知识）、四档评分（AGAIN/HARD/GOOD/EASY）、删除卡片、卡片列表展示下次复习时间。

现有数据表（SQLite）：`review_cards(id, note_id, prompt, fsrs_json, due_at, created_at, was_studied, suspended)`，`review_logs(id, card_id, rating, reviewed_at, due_after)`。注意：`due_at` 和 FSRS 内部统一使用 UTC instant 存储，展示时转换为 Asia/Shanghai。

### 本次目标

改造复习页面，达到三个目标：

1. 创建复习卡片时可以指定「首次复习时间」，FSRS 从该时间起排期后续间隔。
2. 增加未来排期的可视化，让我一眼看出复习压力分布，提升复习效率。
3. 复习事件（卡片）可删除，且可选支持暂停/恢复；操作后排期图即时刷新。

### 需求明细

#### A. 首次复习时间

- 建卡表单新增「首次复习时间」选择，提供四个快捷选项：立即（默认）、今天稍后（当天 20:00）、明天（明天 09:00）、自选（弹出日期时间输入，用 `<input type="datetime-local">`，最小值为当前时间）。
- 前端把所选时间以 `firstReviewAt`（ISO 8601 字符串，本地时间转 UTC）随 `POST /api/reviews` 提交；未传或选「立即」时保持现状（立即到期）。
- 后端 `FsrsReviewScheduler.createCard()` 增加可选参数 `Instant firstReviewAt`：用 FSRS `Card.builder().due(firstReviewAt).build()` 初始化；不传时行为不变。注意保持 UTC 存储、Asia/Shanghai 展示的既有约定。
- 创建成功的提示语中展示卡片首次到期时间。

#### B. 排期可视化

- 新增后端接口 `GET /api/reviews/schedule?days=14`：返回未来 N 天（默认 14，从今天起，按 Asia/Shanghai 日界分组）每天的到期卡片数量和卡片明细列表（id、note_title、prompt、due_at），并包含今天之前已过期未复习的归入「今天」。
- 前端在页面顶部统计区下方新增「未来 14 天复习排期」横向柱状图（纯 CSS/JS 实现即可，不引入图表库）：
  - 每根柱子代表一天，高度按当天到期数量，柱下标注日期（今天用「今」标注并高亮为警示色）。
  - 点击柱子展开/收起当天的卡片明细（标题、问题、具体时间），明细内每项提供「开始复习」和「删除」入口。
  - 删除卡片后柱状图和明细立即刷新。
- 顶部统计卡片改为四项：今日待复习、7 天内到期、卡片总数、已巩固（下次复习间隔超过 21 天的卡片数，可从 fsrs_json 或 due_at 与 created_at 差值近似判断，给出说明即可）。
- 卡片列表（YOUR DECK）每项增加状态标签：新卡（从未复习）、学习中（间隔 < 7 天）、巩固中（7–21 天）、已巩固（> 21 天），并显示「下次复习」的友好格式（今天/明天/具体日期 + 时间）。

#### C. 卡片详情：未来复习日程与遗忘程度圆点

- 在「我的复习卡片」列表中点击任意卡片，展开一条「之后的复习日程」横向时间线（再次点击收起，同一时间只展开一张）。
- 后端新增 `GET /api/reviews/{id}/forecast?count=5`：不动真实卡片状态，复制当前 `fsrs_json` 后用 FSRS 连续按 GOOD 评分推演，返回未来 N 次（默认 5）复习的日期（UTC instant + Asia/Shanghai 展示值），以及每次的 stability。
- 每次复习用一个圆点表示，圆点排成一条带连接线的水平时间线：
  - **颜色深度表示遗忘程度**：主判定依据为该次复习时刻的预计记忆保留率（用 FSRS 记忆衰减公式由 stability 和间隔计算，库内有相应字段则直接用）。若各次保留率都接近目标值、区分度不足，则改用「距上一次复习的间隔长度」作为遗忘程度的代理指标：间隔越长，圆点越深。
  - 用颜色渐变（浅 → 深的一条同色系 ramp，如 `#E24B4A` → `#2C2C2A` 或项目已有的警示色系）映射遗忘程度，不引入新依赖。
  - 每个圆点下方标注：日期（今天/明天/M月d日）、时间和预计保留率百分比；圆点上方悬停或长按显示完整说明。
  - 时间线下方加一行小字图例：「圆点越深 = 预计遗忘越多」。
- 展开态内保留该卡片的「开始复习」「暂停」「删除」入口。

#### D. 删除与暂停

- 保留现有的两步确认删除流程，在排期图明细和卡片列表中均可触发删除；删除时同时清理该卡的 `review_logs`（或按需保留日志，二选一并说明）。
- 利用已存在但未暴露的 `suspended` 字段新增「暂停/恢复」：
  - `POST /api/reviews/{id}/suspend` 和 `POST /api/reviews/{id}/resume`，暂停的卡片不出现在待复习队列和排期图中，列表中标记「已暂停」并提供恢复按钮。

#### E. 视觉与交互约束

- 页面风格必须与现有「雨玻璃」风格一致：沿用 `panel`、`section-kicker`、`count-pill` 等既有 class 和 `review-*.css` 的设计语言，保持简洁，不引入新依赖、不做花哨动画。
- 待复习队列、评分按钮、复习流程的现有交互保持不变。
- 所有时间展示使用 `Asia/Shanghai`，格式友好（今天/明天/M月d日 HH:mm）。
- 响应式：排期图 14 根柱子在窄屏下保持可读（可横向滚动）。

### 验收标准

1. 选择「明天 09:00」创建卡片后，卡片首次 due_at 为明天 09:00（Asia/Shanghai），排期图中明天的柱子 +1。
2. `GET /api/reviews/schedule` 返回的日界与柱状图一致，今天包含已过期未复习的卡片。
3. 删除任一卡片后，统计、排期图、列表同步更新且无刷新页面。
4. 暂停的卡片从队列和排期图消失，恢复后回来，且 FSRS 状态不受暂停影响。
5. 点击卡片展开日程时间线：`forecast` 接口推演结果不写库、不影响该卡片真实的 `fsrs_json` 和 `due_at`；圆点颜色深度随间隔递增，日期/保留率标注正确。
6. `mvn -f backend/pom.xml spring-boot:run` 与 `npm run dev` 联调通过，无控制台报错。

### 实施顺序

1. 后端：`FsrsReviewScheduler.createCard` 支持自定义首次到期 → `ReviewController.create` 接收 `firstReviewAt`。
2. 后端：新增 `GET /api/reviews/schedule`、`GET /api/reviews/{id}/forecast`、suspend/resume 接口。
3. 前端：`reviewApi.js` 补充接口封装 → `ReviewPage.jsx` 加首次复习时间选择、排期柱状图组件（新建 `components/ScheduleChart.jsx`）、卡片展开日程时间线（新建 `components/CardForecast.jsx`）、状态标签、暂停按钮。
4. 自测上述验收标准。
